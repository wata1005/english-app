# Learning Engine and Data Contract v1.1

> **v1.1 provenance.** **[Decided]** = ChatGPT review / parent decision (2026-10-10). **[Draft: Claude Code]** = implementation detail proposed by Claude Code; needs ChatGPT confirmation before Stage A is merged to `main`.

## Architecture
`src/app.html` is the source of truth for the UI; `index.html` is generated by `node tools/build.js`. Do not manually edit `index.html` or `audio/`. No runtime AI API key in the browser.

**[Draft: Claude Code]** Pure logic lives in separate source files that `tools/build.js` inlines into `index.html`:
- `src/engine.js` — storage, `recordAttempt`, scoring, status, compaction, selection. No DOM access.
- `src/catalog.js` — Can-do catalog (flags, scene alternatives) and the mapping from existing games to Can-dos.
- `tests/*.test.js` — unit tests with the Node built-in test runner (`node --test`, Node 22). Browser regression tests run against the built `index.html` in headless Chrome.

## Compatibility **[Decided]**
- Legacy localStorage `eigo-asobi-v1` stays untouched (stars, coins, pet, learned, `level` = age/difficulty, mic, captions, cosmetic items). It is never rewritten or deleted by the learning engine.
- New key **`learner-progress-v1`** (the only name; replaces `learnerProgressV1` in v1 drafts). Schema version 1.
- `curriculumLevel` is distinct from legacy `state.level`.
- New data is written with a guarded JSON parse, schema validation and error recovery. Never retroactively convert stars/coins/learned into verified mastery; they may seed interests/exposure only.

## Interfaces
```ts
type Skill = 'listening'|'speaking'|'reading'|'writing';
type EvidenceMethod = 'action'|'asr'|'parent_observed'|'self_report'|'exposure';
type Recognition = 'not_needed'|'valid'|'uncertain'|'failed';
type Support = 0|1|2|3; // 0 none, 1 replay or prior mistake, 2 visual/Japanese hint or visible answer text, 3 answer highlighted/demonstrated
type Status = 'discovering'|'developing'|'practicing'|'mastered';

interface Attempt {
  id: string; taskId: string; canDoIds: string[]; timestamp: string; // ISO 8601 with offset
  sceneId: string;      // 'game:category', e.g. 'quiz:animals'
  itemId: string;       // the target, e.g. 'dog', 'three-apples', 'b'
  promptType: string;   // e.g. 'where_is', 'pop_the', 'want', 'order', 'letter_name'
  completed: boolean; verified: boolean; firstTry: boolean;
  method: EvidenceMethod; recognition: Recognition; support: Support;
  semanticMatch: number|null; recognitionConfidence: number|null; responseLatencyMs: number|null;
}

interface CanDoAggregate {        // evidence folded in from compacted (deleted) attempts
  attempts: number; validSuccesses: number;
  trials: number;                  // scoring-eligible questions presented (one per question, any support)
  independentSuccesses: number;
  supportHistogram: [number, number, number, number];
  firstIndependentSuccessAt: string|null;
  independentDates: string[];      // distinct local YYYY-MM-DD with an independent success (kept in full)
  independentScenes: string[];     // distinct sceneIds with an independent success (kept in full)
  independentItems: string[];      // distinct itemIds with an independent success (kept in full)
  retentionProbes: number; retentionSuccesses: number;
  lastPracticedAt: string|null;
}

interface CanDoProgress {
  canDoId: string; status: Status; confirmPending: boolean; needsReview: boolean;
  taskSuccess: number|null; independence: number|null; transfer: number|null; retention: number|null;
  masteryScore: number|null; masteredAt: string|null;
  lastPracticedAt: string|null; nextReviewAt: string|null; reviewStep: number;
}

interface LearnerProgress {
  schemaVersion: 1; curriculumLevel: 1|2|3|4;
  attempts: Attempt[];                                 // detailed, rolling window
  aggregates: Record<string, CanDoAggregate>;          // per Can-do, from compacted attempts
  canDoProgress: Record<string, CanDoProgress>;
  levelHistory: { at: string; from: number; to: number; reason: 'recommended_approved'|'parent_manual' }[];
  sessionSummaries: { date: string; engagedSeconds: number; missionsCompleted: number }[];
  settings: { immersion: boolean };
}
```

## Support levels for existing features **[Decided]**
| Situation | support | firstTry |
|---|---|---|
| Correct on the first presentation | 0 | true |
| Pressed "listen again" before answering | 1 | true |
| Correct after a mistake | at least 1 | false |
| Opened hint 1 (Japanese meaning + slow audio) | 2 | as observed |
| Answer word visible in the caption (`capHide` off, or answer revealed) | 2 | as observed |
| Hint 2 (answer highlighted) / Level-1 mole sign showing the target letter | 3 | as observed |

Successes with Japanese meaning or answer text visible (support ≥2) are never independent evidence **[Decided]**. The Japanese hint stays available (parent decision) and simply records `support = 2`.

## Counting rules **[Decided: de-duplication] [Draft: Claude Code: exact window]**
- `recordAttempt` ignores an attempt whose `id` already exists.
- For scoring, successes with the same `canDoId + sceneId + itemId` within **10 minutes** of a previously counted success count once. Failures inside the window are still counted as attempts. This stops rapid repeats of the same question from advancing mastery.
- Only attempts with `method` in {`action`,`asr`,`parent_observed`} and `recognition` not in {`failed`,`uncertain`} are scoring-eligible. ASR failure/uncertainty is recorded but is never a child mistake and never a success.
- `exposure` and `self_report` attempts update `lastPracticedAt` and participation counts only.

## Scoring **[Decided: weights and threshold] [Draft: Claude Code: component formulas]**
All components are 0–100, computed from the union of the detailed attempts and the Can-do's aggregate. If any component is `null`, `masteryScore = null` and the Can-do cannot be mastered. `unknown` is never treated as zero.

- **Task success** = 100 × independentSuccesses / trials, where a *trial* is one scoring-eligible question presented to the child (a question answered after a hint is still a trial, so hints lower this score). `null` until trials ≥ 3.
- **Independence** = 100 × Σ w(support) / validSuccesses, with w(0)=1, w(1)=0.75, w(2)=0, w(3)=0 (a success after a mistake uses its recorded support, so it is at most 0.75). `null` until validSuccesses ≥ 3.
- **Transfer** = 100 if independent successes span ≥2 distinct `sceneId`s (or the scene alternative is met); 50 if 1 scene but ≥2 distinct `itemId`s; 0 if exactly 1 scene and 1 item. `null` if no independent success.
- **Retention**: a *retention probe* is a scoring-eligible first-presentation attempt dated ≥7 calendar days after the first counted independent success. Retention = 100 × retentionSuccesses / retentionProbes (independent successes only). `null` until at least one probe exists.
- **masteryScore** = round(0.40 × taskSuccess + 0.25 × independence + 0.20 × transfer + 0.15 × retention).

Status boundaries and mastery conditions are defined in CAN_DO.md ("Learning status", "Mastery conditions"). The engine applies them in this order: mastered (sticky) → practicing → developing → discovering.

## Record retention and compaction **[Decided: 90 days / 3,000] [Draft: Claude Code: algorithm]**
- Keep detailed attempts for the last **90 days**, at most **3,000** records.
- Compaction runs on initialization and after `recordAttempt` when either limit is exceeded. The oldest attempts are removed first.
- Before an attempt is removed, its contribution is **folded into `aggregates[canDoId]`** for each of its Can-dos: counters, the support histogram, and the dated evidence needed for mastery (`firstIndependentSuccessAt`, `independentDates`, `independentScenes`, `independentItems`, retention probes). These sets are kept in full, so condition checks never lose evidence.
- **Re-evaluation after compaction**: the engine recomputes every affected Can-do from `aggregates + remaining attempts`, using the same formulas as above. The counting rule's 10-minute window only applies inside the detailed window; aggregated successes were already de-duplicated when first counted. Because all mastery inputs are preserved in the aggregate, a Can-do's status after compaction must equal its status before compaction (covered by tests).
- Never deleted by compaction: `canDoProgress` entries with `status = 'mastered'` and `masteredAt`, `levelHistory`, and `aggregates`.
- `sessionSummaries`: keep the last 90 days.
- **Storage full**: if `localStorage.setItem` throws, compact to 1,000 detailed attempts and retry once; if it still fails, keep progress in memory for this session, never interrupt the game, and show a warning only on the parent dashboard.

## Review scheduling
Reviews initially at 1/3/7/14 days after the latest independent success (`reviewStep` 0→3), personalised by demonstrated recall: an independent success advances one step, a failed review goes back one step (minimum 0). No negative feedback loops, compulsive streaks or punitive locks.

## Selection policy
Initial mix: 60% comfortable, 25% stretch, 15% due review; adjust by engagement and evidence, not fixed requirements.

**[Draft: Claude Code]** Until Stage D adds missions, "auto-adjust" means `recommendMissions()` returns 1–2 existing game + category pairs (e.g. `balloon` with `animals`) and the home screen marks them with a small `おすすめ` badge. Nothing is locked; the child can still choose any game.

## Event API
- `recordAttempt(attempt)` validates task/Can-do IDs, rejects invalid attempts, ignores duplicate IDs, appends, applies counting rules, recomputes Can-do progress, schedules the next review, compacts when needed and persists.
- `getDashboardSummary()` returns `{level, levelName, skills, requiredMastered, requiredTotal, confirmPending, recentCanDos, dueReviews, weeklyEngagedSeconds, levelUpRecommended, storageWarning}`.
- `recommendMissions()` filters age-appropriate accessible content (see Selection policy).
- `approveLevelUp()` / `setLevel(level, reason)` change `curriculumLevel` and append to `levelHistory`.
- `resetLearningProgress()` is parent-confirmed, clears only `learner-progress-v1`, and never erases legacy rewards (stars, coins, pet, outfits).

## Speech limitations **[Decided]**
Browser ASR may send audio to providers; parent opt-in required. ASR confidence and semanticMatch are different and must not be conflated. Recognition error/timeout → `recognition='failed'` or `uncertain`, `verified=false`; not counted as a child mistake. Record-and-compare and self-report → participation evidence only. No raw voice persistence by default. Speaking mastery evidence: see CAN_DO.md "Speaking evidence".

## Test plan
1. Legacy save survives initialization; `eigo-asobi-v1` is byte-for-byte unchanged; `state.level` untouched.
2. Duplicate attempt ID ignored; invalid task/Can-do IDs rejected; malformed `learner-progress-v1` recovered with a backup copy.
3. Missing component yields `masteryScore = null`.
4. Supported correct attempt (support ≥2) increases practice but not independent successes.
5. Success after a mistake is not independent.
6. Three same-scene independent successes do not satisfy the 2-scene condition (unless the scene alternative applies).
7. Three successes on the same day do not satisfy the 7-day condition.
8. Same item answered repeatedly within 10 minutes counts once.
9. Status boundaries: 1 → `discovering`, 2 → `developing`, 2 scenes → `practicing`, all conditions → `mastered`.
10. `mastered` is not revoked by later failures; two failed reviews set `needsReview`.
11. ASR failure never becomes an incorrect pronunciation or a verified success.
12. Compaction: status and masteryScore are identical before and after removing old attempts; mastered entries and `levelHistory` survive.
13. Storage-full path keeps the game running.
14. Level-up is recommended only when all required Can-dos are mastered and changes only after approval.
15. Parent reset clears only `learner-progress-v1`.
16. Build output generated with `node tools/build.js`; no hand edits.
17. Smoke-test all existing game modes, pet, outfits, coins, stars, settings and audio.
