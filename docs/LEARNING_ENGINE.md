# Learning Engine and Data Contract v1.2

> **Provenance.** **[Decided]** = ChatGPT review / parent decision (2026-10-10). **[Draft: Claude Code]** = implementation detail proposed by Claude Code. v1.2 applies ChatGPT's second review: task success includes supported correct answers (no double penalty), de-duplication only for the same Can-do + item + scene + prompt, compaction keeps every input needed for de-duplication, retention and rescoring with bounded aggregate size, and English-only mode is an overlay that never rewrites legacy settings.

## Architecture
`src/app.html` is the source of truth for the UI; `index.html` is generated by `node tools/build.js`. Do not manually edit `index.html` or `audio/`. No runtime AI API key in the browser.

**[Draft: Claude Code]** Pure logic lives in separate source files that `tools/build.js` inlines into `index.html`:
- `src/engine.js` — storage, `recordAttempt`, scoring, status, compaction, selection. No DOM access.
- `src/parent.js` — 保護者画面、入場確認、履歴表示（段階C）。
- `src/catalog.js` — Can-do catalog (flags, scene alternatives) and the mapping from existing games to Can-dos.
- `tests/*.test.js` — unit tests with the Node built-in test runner (`node --test`, Node 22). Browser regression tests run against the built `index.html` in headless Chrome.

## Compatibility **[Decided]**
- Legacy localStorage `eigo-asobi-v1` stays untouched (stars, coins, pet, learned, `level` = age/difficulty, mic, captions, cosmetic items). It is never rewritten or deleted by the learning engine.
- New key **`learner-progress-v1`** (the only name; replaces `learnerProgressV1` in v1 drafts). Schema version 1.
- `curriculumLevel` is distinct from legacy `state.level`.
- New data is written with a guarded JSON parse, schema validation and error recovery. Never retroactively convert stars/coins/learned into verified mastery; they may seed interests/exposure only.

## Interfaces
```ts
type Skill = 'listening'|'speaking'|'reading'|'writing';
type EvidenceMethod = 'action'|'asr'|'parent_observed'|'self_report'|'exposure';
type Recognition = 'not_needed'|'valid'|'uncertain'|'failed';
type Support = 0|1|2|3; // 0 none, 1 replay or prior mistake, 2 visual/Japanese hint or visible answer text, 3 answer highlighted/demonstrated
type Status = 'discovering'|'developing'|'practicing'|'mastered';

interface Attempt {
  id: string; taskId: string; canDoIds: string[]; timestamp: string; // ISO 8601 with offset
  sceneId: string;      // 'game:category', e.g. 'quiz:animals'
  itemId: string;       // the target, e.g. 'dog', 'three-apples', 'b'
  promptType: string;   // e.g. 'where_is', 'pop_the', 'want', 'order', 'letter_name'
  completed: boolean; verified: boolean; firstTry: boolean;
  unanswered?: boolean; // true = participation/history only; omitted on older answered records
  counted: boolean;     // repeat decisions are recalculated in timestamp order
  method: EvidenceMethod; recognition: Recognition; support: Support;
  semanticMatch: number|null; recognitionConfidence: number|null; responseLatencyMs: number|null;
}

interface CanDoAggregate {        // evidence folded in from compacted (deleted) attempts; fixed, bounded size
  attempts: number;                // all recorded attempts, for history totals
  unanswered: number;              // unanswered history total, including compacted records
  trials: number;                  // counted scoring-eligible questions presented
  firstTrySuccesses: number;       // counted trials answered correctly on the first selection (any support)
  validSuccesses: number;          // counted valid successes (any support, any try)
  independenceWeight: number;      // Σ w(support) over counted valid successes (see Scoring)
  independentSuccesses: number;
  supportHistogram: [number, number, number, number];
  firstIndependentDate: string|null;   // local YYYY-MM-DD of the first counted independent success
  latestIndependentDate: string|null;  // local YYYY-MM-DD of the latest counted independent success
  independentScenes: string[];     // distinct sceneIds with an independent success, capped at 20
  independentItems: string[];      // distinct itemIds with an independent success, capped at 20
  retentionProbes: number; retentionSuccesses: number;
  lastPracticedAt: string|null;
}

interface CanDoProgress {
  canDoId: string; status: Status; confirmPending: boolean; needsReview: boolean;
  taskSuccess: number|null; independence: number|null; transfer: number|null; retention: number|null;
  masteryScore: number|null; masteredAt: string|null;
  lastPracticedAt: string|null; nextReviewAt: string|null; reviewStep: number;
}

interface LearnerProgress {
  schemaVersion: 1; curriculumLevel: 1|2|3|4;
  attempts: Attempt[];                                 // detailed, rolling window
  aggregates: Record<string, CanDoAggregate>;          // per Can-do, from compacted attempts
  canDoProgress: Record<string, CanDoProgress>;
  levelHistory: { at: string; from: number; to: number; reason: 'recommended_approved'|'parent_manual' }[];
  sessionSummaries: { date: string; engagedSeconds: number; missionsCompleted: number }[];   // last 90 days
  monthlySummaries: { month: string; attempts: number; activeDays: number; engagedSeconds: number }[]; // last 24 months
  settings: { immersion: boolean };   // overlay only; legacy caption/hint settings are never rewritten
}
```

## Support levels for existing features **[Decided]**
| Situation | support | firstTry |
|---|---|---|
| Correct on the first presentation | 0 | true |
| Pressed "listen again" before answering | 1 | true |
| Correct after a mistake | at least 1 | false |
| Opened hint 1 (Japanese meaning + slow audio) | 2 | as observed |
| Answer word visible in the caption (`capHide` off, or answer revealed) | 2 | as observed |
| Hint 2 (answer highlighted) / Level-1 mole sign showing the target letter | 3 | as observed |

Successes with Japanese meaning or answer text visible (support ≥2) are never independent evidence **[Decided]**. The Japanese hint stays available (parent decision) and simply records `support = 2`.

**Answer visibility is evaluated at answer time from the *effective* settings** **[Decided]**: the legacy caption settings with the English-only overlay applied (see CURRICULUM.md "UI language policy"). If the answer word is visible on screen at the moment the child answers (captions shown and not hidden, or already revealed), the attempt records `support >= 2`, whatever mode is active.

## Counting rules **[Decided]**
- `recordAttempt` ignores an attempt whose `id` already exists.
- **Repeat key** = `canDoId + itemId + sceneId + promptType`. Only a success with the **same repeat key** within **10 minutes** of the previous counted success with that key is a repeat; it is stored with `counted = false` and does not affect scoring. Correct answers to **different** items, scenes or prompt types are never treated as repeats, even within the same minute.
- Failures are always `counted = true` (they are real trials).
- `counted` is recalculated in timestamp order for the same repeat key when records arrive out of order. Compaction preserves the boundary repeat keys.
- Only answered attempts (`unanswered !== true`) with `method` in {`action`,`asr`,`parent_observed`} and `recognition` not in {`failed`,`uncertain`} are scoring-eligible. ASR failure/uncertainty is recorded but is never a child mistake and never a success.
- `exposure` and `self_report` attempts update `lastPracticedAt` and participation counts only.

## Scoring **[Decided: weights and threshold] [Draft: Claude Code: component formulas]**
All components are 0–100, computed from the union of the detailed attempts and the Can-do's aggregate. If any component is `null`, `masteryScore = null` and the Can-do cannot be mastered. `unknown` is never treated as zero.

- **Task success (正答率)** = 100 × firstTrySuccesses / trials. A *trial* is one counted, scoring-eligible question presented to the child; a *first-try success* is a trial answered correctly on the first selection, **including supported answers** (after replay or a hint). Support is deliberately ignored here and measured only by Independence, so a hint is never penalised twice **[Decided]**. A correct answer after a mistake is not a first-try success (the games let the child retry until correct, so counting it would make every trial a success). `null` until trials ≥ 3.
- **Independence (自力度)** = 100 × independenceWeight / validSuccesses, where independenceWeight = Σ w(support) with w(0)=1, w(1)=0.75 **[Decided]**, w(2)=0, w(3)=0. A success after a mistake has support ≥1, so it contributes at most 0.75. `null` until validSuccesses ≥ 3.
- **Transfer** = 100 if independent successes span ≥2 distinct `sceneId`s (or the scene alternative is met); 50 if 1 scene but ≥2 distinct `itemId`s; 0 if exactly 1 scene and 1 item. `null` if no independent success.
- **Retention**: a *retention probe* is a scoring-eligible first-presentation attempt dated ≥7 calendar days after the first counted independent success. Retention = 100 × retentionSuccesses / retentionProbes (independent successes only). `null` until at least one probe exists.
- **masteryScore** = round(0.40 × taskSuccess + 0.25 × independence + 0.20 × transfer + 0.15 × retention).

Status boundaries and mastery conditions are defined in CAN_DO.md ("Learning status", "Mastery conditions"). The engine applies them in this order: mastered (sticky) → practicing → developing → discovering.

## Record retention and compaction **[Decided: 90 days / 3,000, no evidence loss, bounded aggregates] [Draft: Claude Code: algorithm]**
- Keep detailed attempts for the last **90 days**, at most **3,000** records. The oldest attempts are removed first, but **attempts from the last 24 hours are never removed**, so the 10-minute repeat window always has its comparison data.
- Compaction runs on initialization and after `recordAttempt` when either limit is exceeded.
- Before an attempt is removed, it is **folded into `aggregates[canDoId]`** for each of its Can-dos. Only `counted` attempts change the scoring fields; the de-duplication decision is already stored on the attempt, so nothing about the 10-minute window has to be reconstructed later.
- **What the aggregate keeps and why** — every field is either a counter or a bounded set, and is exactly what the formulas need:

  | Needed for | Kept as |
  |---|---|
  | Task success | `trials`, `firstTrySuccesses` |
  | Independence | `validSuccesses`, `independenceWeight` |
  | Mastery condition 2 (≥3 independent successes) | `independentSuccesses` |
  | Condition 3 / Transfer (≥2 scenes, or ≥2–3 items for scene alternatives) | `independentScenes`, `independentItems` (distinct values, each capped at 20 — every threshold is ≤3, so the cap never changes a result) |
  | Condition 4 (an independent success ≥7 days after the first) | `firstIndependentDate`, `latestIndependentDate` (the condition holds iff latest − first ≥ 7 days) |
  | Retention | `retentionProbes`, `retentionSuccesses` — whether an attempt is a probe depends only on `firstIndependentDate`, which never changes once set because the oldest attempts are folded first |
  | History / dashboard totals | `attempts`, `supportHistogram`, `lastPracticedAt`, `monthlySummaries` |

- **Rescoring after compaction**: every affected Can-do is recomputed from `aggregate + remaining attempts` with the same formulas. Because each formula input is a sum or a set union over attempts, folding is lossless: status, `masteryScore` and all four components must be identical before and after compaction (covered by tests).
- **Aggregate size**: one fixed-size record per Can-do (22 in v1), sets capped at 20 values. `sessionSummaries` keep 90 days; `monthlySummaries` keep 24 months; `levelHistory` keeps the latest 50 changes. Together with 3,000 detailed attempts this keeps `learner-progress-v1` well under 1.5 MB.
- Never deleted by compaction: `canDoProgress` entries with `status = 'mastered'` and `masteredAt`, `aggregates`, and `levelHistory` (within its 50-entry cap).
- **Storage full**: if `localStorage.setItem` throws, compact to 1,000 detailed attempts and retry once; if it still fails, keep progress in memory for this session, never interrupt the game, and show a warning only on the parent dashboard.

## Review scheduling
Reviews initially at 1/3/7/14 days after the latest independent success (`reviewStep` 0→3), personalised by demonstrated recall: an independent success advances one step, a failed review goes back one step (minimum 0). No negative feedback loops, compulsive streaks or punitive locks.

## Selection policy
Initial mix: 60% comfortable, 25% stretch, 15% due review; adjust by engagement and evidence, not fixed requirements.

**[Draft: Claude Code]** Until Stage D adds missions, "auto-adjust" means `recommendMissions()` returns 1–2 existing game + category pairs (e.g. `balloon` with `animals`) and the home screen marks them with a small `おすすめ` badge. Nothing is locked; the child can still choose any game.

## Event API
- `recordAttempt(attempt)` validates task/Can-do IDs, rejects invalid attempts, ignores duplicate IDs, appends, applies counting rules, recomputes Can-do progress, schedules the next review, compacts when needed and persists.
- `getDashboardSummary()` returns `{level, levelName, skills, requiredMastered, requiredTotal, confirmPending, recentCanDos, dueReviews, weeklyEngagedSeconds, levelUpRecommended, storageWarning}`.
- `recommendMissions()` filters age-appropriate accessible content (see Selection policy).
- `approveLevelUp()` / `setLevel(level, reason)` change `curriculumLevel` and append to `levelHistory`.
- `resetLearningProgress()` is parent-confirmed, clears only `learner-progress-v1`, and never erases legacy rewards (stars, coins, pet, outfits).

## Speech limitations **[Decided]**
Browser ASR may send audio to providers; parent opt-in required. ASR confidence and semanticMatch are different and must not be conflated. Recognition error/timeout → `recognition='failed'` or `uncertain`, `verified=false`; not counted as a child mistake. Record-and-compare and self-report → participation evidence only. No raw voice persistence by default. Speaking mastery evidence: see CAN_DO.md "Speaking evidence".

## Test plan

2. Duplicate attempt ID ignored; invalid task/Can-do IDs rejected; malformed `learner-progress-v1` recovered with a backup copy.
3. Missing component yields `masteryScore = null`.
4. Supported correct attempt (support ≥2) increases practice but not independent successes.
5. Success after a mistake is not independent.
6. Three same-scene independent successes do not satisfy the 2-scene condition (unless the scene alternative applies).
7. Three successes on the same day do not satisfy the 7-day condition.
8. Same Can-do + item + scene + prompt answered repeatedly within 10 minutes counts once; correct answers to different items within the same minute all count.

10. `mastered` is not revoked by later failures; two failed reviews set `needsReview`.
11. ASR failure never becomes an incorrect pronunciation or a verified success.
12. Compaction: status, masteryScore and all four components are identical before and after removing old attempts; attempts from the last 24 hours are never removed; a repeat within 10 minutes of a just-compacted boundary is still detected; mastered entries and `levelHistory` survive; aggregate size stays bounded after 10,000 synthetic attempts.

14. Level-up is recommended only when all required Can-dos are mastered and changes only after approval.

## 段階B: 未回答（2026-10-10）
- `unanswered: true` は出題・参加履歴。`completed=false`, `verified=false` とする。既存レコードの省略値は false と同等。
- 正答率の分母・分子、自力度、支援別集計、転移、保持、習得判定、復習予定・失敗回数には一切加えない。同一問題の成功の重複判定も妨げない。
- 出題数、未回答数、最終参加日時は更新する。圧縮・再読込後も未回答数と評価を維持する。
- 対象は quiz / balloon / mole / shopgame / pet の出題済み・未完了問題。ホーム等への画面離脱、別ゲームへ直接移動、ページ離脱 (`pagehide`) 時に一度記録。再描画・ヒント・かご操作では記録しない。正解後の待ち時間の離脱は追加記録しない。
- 正解前に離脱した問題は、途中の誤操作の有無にかかわらず未回答とする。
- 風船の対象が画面外に出たら未回答。再出題は新しい回答機会として評価し、時間切れだけで自力度を下げない。従来の再出題、効果音、星を付けない報酬ルールは維持する。
- bfcache から戻った場合は同じ問題を再開し、その後の正解または離脱を新しい回答機会として記録する。単なるタブの非表示は離脱扱いにしない。
- 段階Cのダッシュボード・English-only UIは今回実装しない。`eigo-asobi-v1` の形式と既存ゲームの報酬は維持する。

## 段階CでのAPI拡張
`getDashboardSummary()` は `weeklyActiveDays`（操作時間またはミッション完了の記録がある日数）と `weeklyMissionsCompleted` を返す。週次集計は今日を含む7日間で、未来の日付は除外。`recommendMissions()` は既存ゲームの `category` も返す。保護者画面のEnglish-onlyヒント1は日本語の意味を提示せず、再生として記録する。

## 段階D：ミッションの証拠
- ミッションの `taskId` は `mission_<mode>:level<N>`。場面・項目・出題形式とCan-doは各問題に保持し、未回答も同じ出題情報で保存する。
- 出題済みのスキップ、途中離脱、別ゲームへの移動、ページ離脱は `unanswered=true`。支援・評価・復習へ加えない。成功後の遷移は未回答を追加しない。
- アクションは2回のタッチ順まで含めて1問。誤った組み合わせ／順序からの成功は `firstTry=false`。成功前の修正を含む語句タイルの再送も同様。
- 答えが字幕に見える場合、物語本文を表示した場合はsupport>=2。ヒントで答え・順序・お手本を提示した場合はsupport=3。English-onlyのヒント1はゆっくり再生でsupport=1。
- 発話と自力読みの子どもの完了操作は `self_report`、Can-doなし・verified=false。マイクやASRを必須にせず、保護者確認は別記録の `parent_observed`。保護者の入場確認後、支援と最初の回答かを明示的に選択する。アプリ内で提示した支援より低い値にはできず、同じ回答の確認は1回だけ。
- 学習履歴に「本人の申告」「保護者が確認」を区別。読み上げた物語の順序理解を自力読みとして計上しない。CVC語の自力読みと、L4の文の自力読みには絵・自動的なお手本音声を付けない。
- 完了ミッション数は3問を進み終え、実際の回答が1つ以上ある場合にだけ日別記録へ加える。
